# local-rag-agent

Локальный агент для вопросов на естественном языке по личному архиву исследовательских файлов: код Python (`.py`), Jupyter-ноутбуки (`.ipynb`), PDF, изображения (`.png`), DOCX и TXT. Ответы по файлам содержат ссылки на источник: файл и строки, ячейку ноутбука, страницу. На общие вопросы (теория, код с нуля, разговор) агент отвечает из знаний модели и помечает это. Всё работает на локальной машине. Данные корпуса, индексы и трассы в сеть не уходят.

Сейчас индексируются `.py`, `.ipynb`, `.pdf` (включая сканы через OCR), `.docx`, `.txt`, `.md`, `.log`. `.doc` индексируется, если установлен LibreOffice. Изображения `.png` — этап Э5. Подробности — в разделе «Статус» ниже.

## Статус

Проект идёт по двум частям технического задания:

- **Часть 1** (Э1–Э10) — вопросно-ответная система с цитированием над корпусом `.py`, `.ipynb`, `.pdf`, `.png`.
- **Часть 2** (Э11–Э17) превращает её в рабочего ассистента. Добавляются:
  - форматы DOCX и TXT;
  - режим рассуждений;
  - загрузка файлов;
  - код-агент в изолированной песочнице;
  - поиск в интернете.

  Все действия агента в Части 2 проходят через слой политик доступа. Он нужен, чтобы приватные данные не утекли через инъекции в промпт.

**Отступления от ТЗ, известные заранее:**

- **Песочница.** gVisor и Firecracker работают только в Linux. На Windows код будет исполняться в контейнере Docker Desktop, внутри виртуальной машины WSL2:
  - без сети;
  - корпус подключён только на чтение;
  - процесс без прав root;
  - лимиты ресурсов;
  - новый контейнер на каждую задачу.

  gVisor остаётся вариантом для Linux и WSL2.
- **Модель для кода.** Для кода, кроме основной модели, рассматривается специализированная кодовая модель. ТЗ это допускает.

## Требования

- Python 3.11+ и PyTorch. Подходит сборка под ROCm (AMD), CUDA (NVIDIA) или CPU. Проверено на RX 7900 XTX: Windows 11, ROCm 7.2, torch 2.9.
- [Ollama](https://ollama.com) и LLM, по умолчанию `qwen3.5:9b`:
  ```bash
  ollama pull qwen3.5:9b
  ```
- Эмбеддер [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3), около 2.3 ГБ, скачивается с Hugging Face:
  ```bash
  hf download BAAI/bge-m3 --exclude "onnx/*"
  ```
- Реранкер [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3):
  ```bash
  hf download BAAI/bge-reranker-v2-m3
  ```
- Модели Docling для PDF: вёрстка, таблицы, OCR для русского и английского.
  ```bash
  docling-tools models download layout tableformer easyocr --easyocr-lang ru --easyocr-lang en
  ```
- Для оценки: модель-судья, по умолчанию `qwen3.6:27b`:
  ```bash
  ollama pull qwen3.6:27b
  ```

Все модели загружаются только из локального кэша (`embedding.local_files_only`). Во время работы система ничего не скачивает. Если модели нет, ошибка подскажет команду для загрузки.

> **Встроенная графика AMD и Ollama.** Если у процессора есть встроенная графика (например, Ryzen 7000), Ollama может запустить модель на ней, когда дискретная карта занята другой моделью. Запуск тогда падает с ошибкой `ROCm error: device kernel image is invalid`. Чтобы этого не было, ограничьте Ollama дискретной картой и перезапустите Ollama:
> ```bash
> setx HIP_VISIBLE_DEVICES 0
> ```
> Номер карты виден в `%LOCALAPPDATA%\Ollama\server.log`. Команда `rag eval` сама выгружает генератор перед запуском судьи и судью после оценки.

## Быстрый старт

Демо одной командой. Команда соберёт `demo_corpus/`, если его нет, запустит API, проиндексирует корпус и откроет UI:

```bash
make demo          # или: python -m rag_agent.cli demo
```

Запуск по частям:

```bash
rag serve                                  # API на 127.0.0.1:8765
rag ui                                     # интерфейс Streamlit на :8501
```

В интерфейсе выберите рабочую папку, при необходимости поправьте исключения и нажмите «Индексировать». Повторная индексация инкрементальная: разбираются только новые и изменённые файлы, удалённые убираются из индекса.

В чате можно задавать и вопросы по файлам, и общие вопросы. Переключатель «Источник ответа» в боковой панели:

- **Авто.** Маршрутизатор сам решает, нужен ли поиск по файлам.
- **Мои файлы.** Ответ всегда по файлам, со ссылками.
- **Общие знания.** Ответ без поиска, как у обычного ассистента.

Уточняющие вопросы («а где она вызывается?») переписываются с учётом истории диалога в самостоятельный вопрос. Кнопка «Новый диалог» очищает историю.

Переключатель «Думать» управляет режимом рассуждений (Э12):

- **Выкл.** Быстрый ответ без рассуждения.
- **Вкл.** Модель сначала рассуждает, потом отвечает.
- **Авто** (по умолчанию). Маршрутизатор оценивает сложность вопроса: `none` — найти факт, `light` — сопоставить несколько фактов, `deep` — объяснить причину, проверить вывод, спланировать. От уровня зависит бюджет рассуждения: 512 или 1536 токенов.

Бюджет жёсткий: если рассуждение не уложилось, оно обрывается и модель сразу отвечает по черновику (budget forcing). Если быстрый ответ в авторежиме не подтверждён ссылками, он повторяется с рассуждением. Рассуждение показывается свёрнутым блоком «Черновик рассуждений». Это не объяснение ответа: подтверждение — только ссылки на источники. В историю диалога рассуждение не попадает.

CLI без UI:

```bash
rag index "C:\path\to\WorkSpace" -x "Аккаунты"
rag ask "Какой learning rate использовался в эксперименте с аугментациями?"
rag ask "Что такое ROC-AUC?"                  # маршрутизатор ответит из общих знаний
rag ask "Почему step-расписание хуже?" --reasoning on   # off | on | auto
rag symbols calc_metrics                      # где определена и где вызывается (без LLM)
rag status
```

## Как устроено

```
файлы ─► walker (исключения) ─► парсеры .py (AST) / .ipynb (граф ячеек) / .pdf (Docling, OCR) / .docx / .txt ─► узлы + связи
        ─► BGE-M3 (dense + sparse) ─► Qdrant                            ┐
        ─► SQLite-каталог (files, nodes, edges, symbols, calls)         ┘

вопрос (+ история) ─► маршрутизатор ─┬─ corpus  ─► поиск ─► LLM (JSON: answerable, answer [n], general) ─► ответ с цитатами
                                     └─ general ─► LLM ─► ответ из общих знаний

поиск: BGE-M3 dense (top-40) ─► реранкер bge-reranker-v2-m3 ─► RRF с определениями и вызовами имён из вопроса ─► top-6
```

- **Единая модель данных** (`schema.py`). Файл разбирается на узлы: фрагмент кода, markdown-ячейка, ячейка кода, вывод ячейки и т. д. Между узлами хранятся типизированные связи: `contains`, `produces` (ячейка → её вывод) и другие.
- **Ноутбуки — граф ячеек.** Каждая ячейка становится отдельным узлом. Вывод ячейки — тоже отдельный узел: он обрезается с сохранением хвоста, где обычно стоят итоговые метрики, и индексируется вместе с кодом, который его породил (связь `produces`). В заголовок каждой ячейки добавляется название ноутбука и путь по разделам («Бейзлайн: логистическая регрессия > Обучение»). Связи `uses_var` показывают, из какой ячейки пришла переменная: это статическая нижняя оценка потоков данных, как в синтаксической стадии CRABS.
- **Код `.py` — AST-чанкинг** в духе cAST. Функции и классы не разрезаются, мелкие соседние определения склеиваются до лимита. Большой класс делится на заголовок и группы методов, у каждой группы в контексте указан класс. Декораторы и комментарии над функцией остаются с ней. Нарезка окнами по строкам осталась как бейзлайн: `chunking.python: lines`.
- **Символы и вызовы.** Статический анализ собирает определения функций и классов и места вызовов, включая ячейки ноутбуков. Из них строится точный поиск имён: если в вопросе есть имя из корпуса, в выдачу добавляются его определение и места вызова. Та же таблица отвечает на вопрос «где вызывается X» без LLM: `rag symbols X`.
- **PDF** разбирается Docling: модель вёрстки на DocLayNet восстанавливает порядок чтения многоколоночных страниц, TableFormer — структуру таблиц. Узлы — разделы с диапазоном страниц, таблицы в Markdown, рисунки с подписями. OCR (EasyOCR, ru/en) запускается, только если у страниц нет текстового слоя.
- **DOCX** читается из XML без моделей: иерархия заголовков, таблицы, рисунки с подписями, свойства документа. Правки в режиме рецензирования принимаются в действующем тексте, а удалённое и вставленное хранится отдельными узлами, как и комментарии рецензентов. Их можно найти по прямому вопросу («какие правки вносились?»), но с действующим текстом они не смешиваются.
- **TXT, MD, LOG.** Кодировка определяется автоматически (Windows-1251 тоже). Тип содержимого определяется эвристикой: markdown, лог, таблица, код, проза. Из логов обучения извлекаются метрики по эпохам — лучшее и последнее значение — в отдельный узел-сводку.
- **Поиск.** Первая стадия — плотный поиск BGE-M3; режимы `sparse` и `hybrid` доступны, но на демо-корпусе не помогли. Затем кросс-энкодер переупорядочивает 40 кандидатов, и в конце результаты сливаются через RRF с точными совпадениями имён.
- **Индексы.** Для каждой комбинации «папка × эмбеддер × настройки чанкинга» создаётся отдельный индекс. Поэтому абляции переключаются без переиндексации ранее построенных вариантов.
- **Маршрутизатор** (`router.py`) одним вызовом LLM со structured output выбирает маршрут `corpus` или `general` и переписывает уточняющий вопрос в самостоятельный. При сомнении выбирается `corpus`. Если ни одна папка не проиндексирована, ответ даётся из общих знаний с пометкой.
- **Ответ.** Генерация идёт со structured output: JSON-схема, декодирование ограничено сервером. Ссылки `[n]`, не соответствующие найденным фрагментам, удаляются. Если ответа в найденном нет, модель должна отказаться.

```
src/rag_agent/
  config.py        настройки: configs/default.yaml < configs/local.yaml < RAG__SECTION__KEY
  schema.py        узлы, связи, локации
  ingest/          обход папки и парсеры: python, notebook, pdf (Docling), docx, txt; статический анализ кода
  index/           эмбеддер, Qdrant, SQLite-каталог, инкрементальный индексатор
  router.py        маршрутизатор corpus / general, переписывание уточняющих вопросов
  retrieval.py     dense / sparse / hybrid, реранкер, точный поиск имён, RRF
  generation.py    промпт, JSON-ответ, разбор цитат
  llm.py           Ollama или любой OpenAI-совместимый API

  api.py, ui.py, cli.py
```

## Оценка качества

```bash
rag eval                                   # демо-набор, ответы + LLM-судья
rag eval --retrieval-only --mode hybrid    # только метрики поиска
rag eval путь/к/набору.yaml --no-judge     # свой набор, без судьи
rag eval-validate путь/к/набору.yaml       # проверить разметку по индексу
rag ablate configs/ablations/e3.yaml       # таблица абляций: несколько конфигураций на одном наборе
rag rejudge configs/ablations/e13.yaml runs/ablations/<папка>   # заново к судье, ответы не генерируются
rag ablate-code configs/ablations/e15.yaml # код-агент: задачи со скрытыми проверками в песочнице
python scripts/redteam_code.py             # опасный код в песочнице (Э17), без модели
python scripts/h9_monitoring.py            # мониторинг на канареечных запросах (Э9, pip install driftfdr)
make check                                 # секреты и личные пути в файлах репозитория (то же в CI)
```

По умолчанию используется `evalsets/demo_v4.yaml` (Э12: документы и 16 вопросов, требующих рассуждения); наборы прежних этапов — `demo_v3.yaml` (Э4), `demo_v2.yaml` (Э3) и `demo_v1.yaml` (Э2). Результаты пишутся в `runs/eval/<дата>-<имя>-<режим>/`: `report.md`, `summary.json`, `results.jsonl`, `config.json`. Папка `runs/` не коммитится.

Считаются метрики из раздела 5.2 ТЗ:

- **Поиск:** Recall@k, Hit@k, MRR, nDCG@10, в разрезе классов и типов файлов.
- **Маршрутизатор:** точность.
- **Ответы:** обязательные элементы ответа, корректность и верность контексту по оценке LLM-судьи, точность цитирования (по разметке и по судье), релевантность.
- **Отказы:** precision и recall отказов на неотвечаемых вопросах (Q6).
- **Латентность:** p50 и p95.
- **Рассуждения:** точность против сгенерированных токенов и задержки по классам вопросов, доля вопросов с рассуждением, доля обрезанных по бюджету, доля лишних токенов без прироста точности.

Для основных метрик считается 95% бутстреп-интервал.

**Свой эталонный набор** для приватного корпуса — главный артефакт проекта (ТЗ, S9). Формат описан в шапке [evalsets/demo_v1.yaml](evalsets/demo_v1.yaml). Эталонные источники задаются как `{file, cell}` или `{file, lines}`, поэтому разметка не зависит от способа чанкинга и переживает абляции. Кладите приватные наборы в `evalsets/private/`, эта папка не коммитится.

## Конфигурация

Все параметры задаются в `configs/default.yaml`. Для машинно-специфичных настроек создайте `configs/local.yaml`, он не коммитится. Любой ключ можно переопределить переменной окружения, например `RAG__LLM__MODEL=qwen3.6:27b` или `RAG__RETRIEVAL__MODE=hybrid`.

## Приватность

- Индексы, каталоги и трассы хранятся в `~/.local-rag-agent`, вне репозитория.
- Собственный репозиторий и каталог данных никогда не индексируются, даже если лежат внутри выбранной папки.
- Папки с чувствительными данными добавляйте в исключения. По умолчанию уже исключены `Аккаунты`, а также `.git`, окружения и все скрытые папки.
- Содержимое файлов подаётся модели как данные. Промпт запрещает выполнять инструкции из фрагментов.
- Телеметрия Streamlit отключена в `rag ui`.

## Разработка

```bash
python -m pytest -q
```

Тесты используют поддельные эмбеддер и LLM. Им не нужны GPU, модели и приватные данные, поэтому они идут в CI.
