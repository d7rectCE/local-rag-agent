# Э13. Загрузка файлов в разговор

Критерий приёмки (ТЗ ч.2): выполнено FR12, проверена H12.

- **FR12:** загрузка файлов через интерфейс — проверка, разбор, сессионная область, срок хранения, явное добавление в корпус.
- **H12:** Self-Route для загрузок сопоставим по точности с подачей файла целиком при меньшей стоимости (Li и др., EMNLP 2024 [16]).

Набор — [`evalsets/uploads_v1.yaml`](../evalsets/uploads_v1.yaml): 18 вопросов Q7 по трём файлам. Файлы собираются скриптом `scripts/build_demo_uploads.py`:

| Файл | Размер | Относительно бюджета (≈16 000 символов) |
|---|---|---|
| `contract_small.docx` — договор НИР | ~2 500 символов | помещается целиком |
| `cluster_rules_medium.md` — регламент вычислительного кластера | ~16 600 символов | на границе |
| `lab_journal_large.txt` — журнал экспериментов за год: 756 запусков таблицей и 4 события | ~126 000 символов | в 7–8 раз больше |

Генератор — `qwen3.5:9b` с окном 16k токенов, судья — `qwen3.6:27b`. Спецификация прогона — [`configs/ablations/e13.yaml`](../configs/ablations/e13.yaml), таблицы — [`reports/e13/`](e13).

## Что сделано

«Загрузил, спросил, забыл» (S16). Файл живёт в области сессии `data_dir/uploads/<сессия>` `uploads.ttl_hours` (24 ч) и попадает в корпус только по явной кнопке «Добавить в корпус». Файл копируется в папку `uploads/` корпуса, существующий файл не перезаписывается, дальше работает обычная инкрементальная индексация.

При загрузке:

- **Тип определяется по содержимому, а не по расширению.** PDF — по сигнатуре; DOCX — ZIP-архив с `word/document.xml`; ноутбук — JSON с `cells`; текст — по декодируемости. Исполняемые файлы, другие архивы и неизвестные двоичные форматы отклоняются. Размер ограничен (`uploads.max_mb`), DOCX проверяется на ZIP-бомбу.
- **Разбор идёт в отдельном процессе с таймаутом.** Испорченный файл не может повесить или уронить сервис.
- **Файл, совпадающий с файлом корпуса по SHA-256,** помечается как дубликат.
- **Фрагменты индексируются во временный индекс загрузки.** Он хранится в памяти и в папке сессии, общий индекс корпуса не трогается.
- **Всё прочитанное из загрузки — недоверенные данные для слоя политик Э14.** Модель получает пометку, что инструкции из файла не выполняются.

**Маршрутизация (Self-Route, Li и др. [16]).** Эффективный бюджет — треть окна модели: по RULER качество длинного контекста падает задолго до его формальной длины. Это `uploads.context_share` × `llm.num_ctx` × ~3 символа на токен ≈ 16 000 символов.

| Путь | Когда | Как |
|---|---|---|
| `whole` | файл в бюджете | весь файл в контекст |
| `index` | файл больше бюджета | поиск по временному индексу (кросс-энкодер поверх косинуса), ответ по найденным фрагментам |
| `index+parts` | модель сказала, что найденного не хватает (`answerable=false`) | файл читается целиком по частям: каждая часть отдельным вызовом отмечает фрагменты по вопросу (map), ответ пишется по отмеченным (reduce) |

Настройки для абляции: `uploads.route: self_route | whole | index`.

## Результаты

Три пути на всех 18 вопросах ([`reports/e13/ablation_prejudge.md`](e13/ablation_prejudge.md)). Точность — доля ответов с обязательными элементами эталона (`must_include`: число, дата, имя запуска). Это автоматическая метрика, от судьи она не зависит. Оценки судьи в этом прогоне недействительны (см. «Разбор»). Переоценка сохранённых ответов исправленным судьёй (`rag rejudge`) стоит в очереди после обучения детектора; её числа будут добавлены сюда.

Токены — на вопрос, включая вызовы map при чтении по частям.

| Путь | Малый (договор) | Средний (регламент) | Большой (журнал) | Токенов на вопрос, большой | Задержка p50 / max, большой, с |
|---|---|---|---|---|---|
| **Self-Route** | 6/6 (целиком) | 6/6 (индекс) | **4/6** (индекс 4, по частям 2) | 35 600 | **7.1** / 82.6 |
| всегда целиком (большой — по частям) | 6/6 | 6/6 (по частям) | 4/6 | 81 400 | 41.0 / 57.4 |
| только временный индекс | 6/6 (индекс) | 6/6 | 2/6 | **7 400** | 7.1 / 25.9 |

**H12 на этом наборе поддерживается** (по автоматической метрике, до переоценки судьёй). Self-Route отвечает на большом файле так же, как чтение целиком (4 из 6), тратит 44% токенов и отвечает с медианной задержкой почти в 6 раз меньше. Только индекс в 5 раз дешевле, но теряет половину ответов.

На малом и среднем файлах все три пути отвечают на все вопросы. Средний файл (16 600 символов) чуть больше бюджета, и Self-Route отвечает по индексу. Путь «целиком» читает его по частям за 4.3 раза больше токенов, без выигрыша в точности.

Где какой путь нужен на большом файле:

| Вопрос | Индекс | По частям | Почему |
|---|---|---|---|
| u-l-01 «что произошло 14 марта 2025» | ✓ | ✓ | дата в вопросе словами, в журнале — `2025-03-14`: находит точное совпадение ключа |
| u-l-04 «параметры запуска run-431» | ✓ | ✓ | имя запуска — точное совпадение |
| u-l-03 «какие результаты признаны недействительными» | ✗ | ✓ | событие в одной строке из 756, поиск его не поднимает; map находит |
| u-l-05 «на какой оптимизатор перешли для ViT-S/16 в ноябре» | ✗ | ✓ | то же |
| u-l-02 «с какой даты часть запусков на cifar10-subset-v2 и почему» | ✗ | ✗ | map отметил не те части; имя датасета встречается больше чем в 20% фрагментов и не различает их |
| u-l-06 «какой запуск за год показал лучшую val accuracy» | ✗ | ✗ | агрегат по 756 строкам: нужен расчёт, а не чтение |

Self-Route выбрал путь «по частям» ровно там, где индекса не хватило (u-l-03, u-l-05). Там, где индекс ответил верно, модель сказала «хватает», и дорогое чтение не запускалось. u-l-02 и u-l-06 модель по индексу ответила уверенно и неверно, поэтому Self-Route до частей не дошёл. Для u-l-06 это не повредило: по частям тоже не выходит. Ложная уверенность по неполному контексту — известное ограничение Self-Route [16].

## Разбор: почему большой файл сначала давал 1 из 6

Первые прогоны давали на большом файле 1–2 из 6 во всех трёх путях, даже при чтении целиком. Найдены четыре независимые причины, все исправлены.

1. **Таблица TXT резалась на 40-строчные куски, каждый обрезался на 6000 символах** (c8b9bd3). Терялось около 9% строк журнала, в том числе нужные. Теперь строки пакуются по размеру, у каждой сохраняется номер строки, заголовок над таблицей — отдельный фрагмент.
2. **Генератор видел только первые 2500 символов каждого фрагмента** (`generation.max_source_chars`), а табличный фрагмент — до 6000 (b22760b). Ответ «про run-431 в источниках ничего нет» при run-431 во фрагменте объясняется этим. Для загрузок фрагменты теперь подаются целиком в пределах бюджета контекста. Путь корпуса не менялся: из 149 фрагментов демо-корпуса длиннее 2500 символов только один.
3. **Плотный поиск не отличает run-431 от run-413** в журнале из сотен похожих строк, а «14 марта 2025» не похоже на `2025-03-14` (b22760b). Даты вопроса (словами и в ISO) и имена с цифрами теперь ищутся буквально. Фрагменты с редкими ключами (не больше чем в 20% фрагментов) ставятся первыми в поиске и всегда попадают в reduce при чтении по частям.
4. **Судья видел только первые 2000 символов** каждого процитированного фрагмента (8ee575e). Верный ответ о run-431 с правильными числами он оценил как выдуманный: «во фрагментах перечислены только run-101, run-418–427». Теперь судья видит до 8000 символов, не меньше генератора. Поэтому оценки судьи этого прогона недействительны: ответы будут переоценены без повторной генерации.

Причины 2 и 4 касаются не только загрузок. Любой фрагмент длиннее лимита генератора или судьи молча обрезается. Для корпуса это пока один фрагмент — лог обучения на 3780 символов. Но при `chunking.max_chunk_chars` 6000 против `generation.max_source_chars` 2500 такие фрагменты появятся на любом корпусе с длинными таблицами. Лимиты стоит согласовать при следующей переиндексации.

## Ограничения

- **Шесть вопросов на большой файл.** Разница «4 из 6 против 4 из 6» не доказывает равенство, она лишь его не опровергает. Для строгой проверки нужен набор побольше, с вопросами разных типов: точный факт, редкое событие, агрегат.
- **Агрегатные вопросы по большим таблицам** (u-l-06) не решает ни один путь. Им нужен расчёт: загрузить таблицу во временную SQLite и дать SQL-инструмент Э6, как для каталога экспериментов.
- **Судья пока старый.** Оценки судьи, включая «верность контексту», будут добавлены после переоценки.
