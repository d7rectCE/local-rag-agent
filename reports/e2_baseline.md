## Разбор ошибок

1. **Основная причина ошибок — поиск по ноутбукам.** Recall@5 по `.ipynb` равен 0.52, по `.py` — 0.82. Все 5 ложных отказов (q1-02, q1-10, q3-01, q4-06, q5-06) случились, когда нужная ячейка не попала в контекст. Например, ячейка с выводом `roc_auc: 0.998` сама по себе не содержит слов «логистическая регрессия»: они есть только в заголовке ноутбука. Генератор при этом ведёт себя правильно и отказывается, а не выдумывает. Отсюда верность контексту 0.95 при корректности 0.80.
   **Что проверить на Э3:** добавлять заголовок ноутбука и путь разделов в контекст каждой ячейки (граф ноутбука из S3).
2. **Q2 «где вызывается».** Вызовы `calc_metrics` разбросаны по 7 местам (q2-02), а поиск по смыслу находит 1–2 из них. Ожидаемо, это задача для точного поиска идентификаторов и графа вызовов (S2, S5), в чистом RAG она не решается.
3. **Маршрутизатор ошибся 2 раза из 50.** Навигационные вопросы без слов «мой» и «у меня» ушли в общие знания: «Where is the model factory defined…» и «Какая функция рисует матрицу ошибок и где она используется?». В ответ на них пришёл общий ответ про scikit-learn. Промпт маршрутизатора специально не подгонялся под эталонный набор. Улучшать его нужно на отдельной dev-выборке, иначе оценка станет смещённой.
4. **Q4 (визуальные).** Изображения пока не индексируются. Ответы находятся только косвенно, через код построения графика. Например, красная точка на q4-06 определена по коду `plot_param_curve`, а не по картинке. Это цель Э5.
5. **must_include (0.66) строже судьи (0.80).** Часть ответов верна по смыслу, но не содержит нужной формы, например пути `features.py` или слова `macro`. Для чисел оба критерия согласуются.

## Ограничения оценки

- **Судья не откалиброван.** Он из того же семейства (Qwen), что и генератор. ТЗ (S9) требует проверить согласие судьи с ручной разметкой на 30–50 ответах. Для этого нужны ручные метки: файл `results.jsonl` каждого прогона содержит всё необходимое для разметки. До калибровки абсолютные значения корректности — ориентир. Сравнения конфигураций с одним и тем же судьёй корректнее.
- **Демо-корпус мал:** 16 файлов, модули `.py` не длиннее 60 строк. Поэтому каждый `.py` целиком помещается в одно окно, и гипотезу H1 (AST-чанкинг) на нём проверить нельзя. Для Э3 корпус нужно расширить длинными модулями.
- **Эталонный набор составлен автором корпуса.** Основным артефактом по ТЗ остаётся ручной набор на 100–150 вопросов по приватному корпусу.
